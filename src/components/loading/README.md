# RA — экран загрузки для Next.js

Геометрия вытащена **напрямую из `ra_logo.blend`**: распакован zstd-контейнер,
разобраны DNA-блоки, забраны вершины и треугольники меша. Это настоящая
3D-модель твоего знака, а не обводка скриншота. Плоский вектор контура тоже
есть — `public/ra-logo.svg`, 97 точек, один замкнутый путь.

Цвета сняты пипеткой с твоего рендера: фон `#090400` → `#070401`, знак `#FA8A16`.

## Что происходит на экране

Знак **собирается из осколков собственного 3D-меша**. Это буквально та же
геометрия, что лежит в `ra_logo.blend`: 610 вершин, 384 треугольника —
передняя грань, задняя и боковины экструзии.

1. Осколки разлетаются наружу, каждый со своей осью вращения и своей задержкой.
2. По мере загрузки они возвращаются на места — слева направо, чтобы сборка
   читалась как жест, а не как общий наплыв.
3. Знак одновременно доворачивается к камере и подъезжает из глубины.
4. Когда собрался — еле заметно покачивается, разгорается ореол, экран уходит.
5. Фоном плывёт тёплая жёлтая пыль.

Освещение и материал считаются в шейдере: ключевой свет сверху-слева,
заполняющий снизу-справа, контровой ободок по краю силуэта. Нормали
фасеточные, поэтому грани читаются по отдельности.

## Файлы

Разложено по структуре этого проекта:

```

  ra-mesh.ts                 — геометрия из .blend, base64 (Float32 + Uint16)
  DustField.tsx              — фоновая пыль на canvas

  preview.html               — открыть в браузере, чтобы посмотреть вживую
```

`BootGate.tsx` и `layout.example.tsx` из поставки удалены: контент здесь
скрывается не обёрткой, а атрибутом `data-loading` на `<html>`, который ставит
инлайновый скрипт в `app/layout.tsx` ещё до первой отрисовки. Обёртка поверх
этого дала бы второй механизм скрытия и лишний `<div>` вокруг всей страницы —
а от него поехали бы `position: fixed` в хедере и замеры GSAP.

## Зависимость

`three` (+ `@types/three`) уже установлен в проект — `bun add three`.
Больше ничего — ни R3F, ни постпроцессинга. Сцена весит 384 треугольника,
свечение сделано CSS-градиентом поверх, а не bloom-пассом.

## Подключение в этом проекте

Экран уже подключён — через `components/Preloader.tsx`, который стоит в
`app/layout.tsx` рядом с `{children}`. Отдельного `<LoadingScreen />` в layout
нет: обёртка добавляет две вещи, без которых на этом сайте нельзя.

**Потолок по времени.** Авто-режим ждёт `window.load` без дедлайна, поэтому один
подвисший запрос оставил бы посетителя на 92% навсегда. Через 4 секунды от
начала навигации `Preloader` передаёт `progress={100}` — экран переключается в
управляемый режим и досчитывается принудительно.

**Передача эстафеты.** Все интро-анимации сайта ждут атрибут `data-app-ready`
(см. `lib/appReady.ts`). Поэтому `onDone` вызывает `markAppReady()`: без этого
герой соберётся под экраном загрузки и закончится раньше, чем его увидят.

Скролл на время загрузки блокирует не компонент, а правило
`html[data-loading] body { overflow: hidden }` в `globals.css` — оно работает с
первой отрисовки, а не с гидрации.

## Пропсы

| Проп          | Тип          | По умолчанию | Что делает                                                            |
| ------------- | ------------ | ------------ | --------------------------------------------------------------------- |
| `progress`    | `number`     | —            | 0–100. Если передан — управляешь прогрессом сам, авто-режим выключен.  |
| `minDuration` | `number`     | `2200`       | Минимальное время показа в мс, чтобы экран не моргал на быстрой сети.  |
| `label`       | `string`     | `'Loading'`  | Подпись слева от процентов, моноширинная.                              |
| `onDone`      | `() => void` | —            | Вызовется после того, как экран полностью исчез.                       |

### Ручной прогресс

```tsx
const [p, setP] = useState(0);

useEffect(() => {
  const urls = ['/hero.webp', '/bg.webp' /* ... */];
  let done = 0;
  urls.forEach((u) => {
    const img = new Image();
    img.onload = img.onerror = () => setP((++done / urls.length) * 100);
    img.src = u;
  });
}, []);

return <LoadingScreen progress={p} />;
```

## Шрифт ANGRY

ANGRY — жирный геометрический дисплей Игоря Степанченко (2020), с хорошей
кириллицей. В типографике экрана два уровня и они не пересекаются:

- **дисплейный** — ANGRY, подпись `Loading`, трекинг `0.28em`;
- **утилитарный** — моноширинный, только цифры процентов (с `tabular-nums`,
  чтобы ширина не прыгала при счёте).

В проекте ANGRY уже подключён через `next/font/local` в `app/layout.tsx`
(`public/Angry.otf` → переменная `--font-display`), поэтому `@font-face` из
поставки удалён, а `--ra-display` в CSS-модуле ссылается на ту же переменную.
Второй `@font-face` тянул бы копию шрифта отдельным запросом и возвращал FOUT,
ради которого `next/font` и стоит.

**Проверь лицензию на коммерческое использование** перед боевым запуском —
на разных зеркалах условия описаны по-разному, надёжнее уточнить у автора.

## Почему знак не «вылезает из квадрата»

Первая версия страдала ровно этим, и причин было две.

**Кадр был слишком тесный.** При `camera.position.z = 4.2` и fov 34° полукадр
равен 1.28, а полуширина знака — 1.0. То есть на разлёт оставалось 0.28, тогда
как осколки улетали на 3.1 — в 2.4 раза за край. Всё, что вылетало, срезалось
границей канваса ровной прямой, и это читалось как прямоугольник. Камера
отодвинута на 6.2 — запас стал 0.9, — а контейнер увеличен, чтобы знак не
уменьшился на экране.

**Облако разлёта было кубическим.** Разброс задавался как `(random - 0.5)` по
каждой оси независимо — это равномерное заполнение куба, и его углы видно.
Теперь направление берётся равномерно по сфере (отбраковкой из шара), а радиус
через `cbrt`, чтобы объём заполнялся ровно, без комка в центре.

Сверху на канвас положена мягкая радиальная маска: осколок, долетевший до
границы, растворяется, а не обрубается. Это страховка — при любом разлёте
прямых срезов больше не будет.

## Про плавность

Сборка целиком считается в вершинном шейдере: у каждого треугольника свои
атрибуты — центроид, вектор разлёта, ось вращения и задержка, — а на CPU
меняется ровно один uniform `uProgress`. Одна геометрия, один draw call,
384 треугольника.

`--p` пишется прямо в DOM через ref, мимо React. В состоянии живут только целые
проценты, поэтому React перерисовывается ~100 раз за загрузку, а не 60 раз
в секунду.

Сглаживание считается от `dt`, а не от кадра — на 120-герцовом экране скорость
сборки та же, что и на 60-герцовом.

Свечение — обычный div с радиальным градиентом, у которого меняются только
`opacity` и `transform`. Это композиторские свойства, они идут на GPU.

## Подкрутить под себя

Всё живёт в CSS-переменных в начале `.root`:

```css
--void: #070401; /* фон               */
--flame: #fa8a16; /* основной оранжевый */
--glow: #ffb459; /* подписи            */
```

- Размер сцены — `.scene { width/height }` плюс `camera.position.z`. Эти два
  числа связаны: контейнер задаёт размер на экране, камера — сколько места
  вокруг знака остаётся осколкам.
- Скорость сборки — делитель `170` в `tick()` внутри `LoadingScreen.tsx`.
- Подпись — проп `label`. Кириллица работает: `label="Завантаження"`.
- Сила ореола — `.bloom { opacity }`; кривая `var(--p) * var(--p)` держит
  свечение слабым почти до конца и разгоняет его на финише.
- Дальность разлёта — `r` в `RaLogo3D.tsx`: сейчас `0.55 + cbrt(rand) * 1.0`.
  Увеличишь — отодвинь и камеру, иначе осколки снова упрутся в край.
- Порядок сборки — формула `d` там же: сейчас `(cx + 1) / 2` даёт слева
  направо. Поменяй на `cy` — пойдёт снизу вверх, на `Math.random()` — вразнобой.
- Кручение осколков — множитель `3.4` в вершинном шейдере.
- Материал — три uniform-цвета `uDark` / `uMid` / `uHot`.
- Покачивание собранного знака — амплитуды `0.13` и `0.06` в `loop()`.
- Пыль: плотность — проп `density` у `<DustField />` (по умолчанию `62` пылинки
  на миллион пикселей, потолок — 180 штук). Цвет — две строки `rgba(...)`
  в конце `draw()` внутри `DustField.tsx`. Скорость — множитель у `m.vy`
  в `build()`. Радиус свечения ближних — `m.r * 5`.
- Моноширинный шрифт: подставь свой через `--ra-mono`, например
  `--ra-mono: var(--font-geist-mono)` из `next/font`.

## Мелочи, о которых легко забыть

- Фон `body` в `globals.css` уже тёмный (`#090400`), поэтому между первой
  краской и монтированием компонента белым не мигает. Если будешь менять — эти
  два цвета должны оставаться близкими.
- `ra-logo.svg` использует `currentColor` — можно красить через CSS.
